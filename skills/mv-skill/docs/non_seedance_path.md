# Non-Seedance Keyframe Path (non-lipsync segments)

## When this document applies

**Trigger**: `creative_proposal.model_primary` (the non-lipsync model) is **not** a Seedance 2.0 variant — i.e. `model_primary ∉ {seedance-2-0, seedance-2-0-fast}`. This is decided in Phase 02 Decision 3 and can also be reached if the model is changed later (see Phase 06).

For those projects, **non-lipsync segments are generated by the KEYFRAME path** — first generate 1-N keyframe image(s) (the same Phase 05b machinery lipsync uses), then image-to-video — instead of the Seedance asset-reference path (`ark_asset_ids` + `@assetN`).

**This document REPLACES, for non-lipsync segments only, the Seedance-specific rules in the standard `PHASE.md` / `SKILL.md`**: ARK registration, `@assetN` / `ark_asset_ids`, the single-path rule, and "a character segment needs the character ref even with a keyframe". Everything else in each phase is unchanged.

- **Lipsync segments are unaffected** — always `dlai2v_pro`, keyframe-driven via Phase 05b, regardless of this document.
- **The Seedance asset-reference path is unchanged** — when `model_primary` is a Seedance variant, follow the standard `PHASE.md` exactly; do not read this document.

**How to read**: jump to the section for your current phase.

## Why (one paragraph)

ARK asset-reference (`dl asset register` → `@assetN`) is Seedance-only; other models cannot consume it. So instead of feeding a reference and a placeholder, the keyframe path **bakes identity + scene into a generated keyframe image** (gpt-image-2 from the 2-panel character reference sheet), then the video model simply animates that keyframe via its image-to-video contract. Identity is locked in the keyframe, not in a model-specific reference channel — robust and model-agnostic. This is exactly how lipsync segments already work; the keyframe path just extends it to non-lipsync segments.

---

## Phase 02 — Segmentation

Each keyframe-path non-lipsync segment is **one image-to-video call seeded by its own keyframe(s) of a single scene**. Therefore:

- **Each scene change must cut to a new segment** — keyframe-path non-lipsync segments **do not span scenes**, even if the chosen model happens to accept multiple input images. (This is the "does not support multi-image reference" branch in `references/treatment_director.md`, made unconditional for every non-Seedance model. There is no third "plain multi-image" path.)
- All other segmentation discipline is unchanged: full-track coverage, frame alignment, cut points on lyric onset / downbeat, `duration ∈ [4, cap]`, and `lip ↔ non-lip switch = new boundary`.

Result: scene changes are carried by segment count, not by intra-segment scene lists.

---

## Phase 04 — References (no ARK)

Generate the **same** character (2-panel reference sheet) / location / prop references as the standard path — entity extraction, single-look vs multi-look, portrait + PORTRAIT SELF-CHECK for multi-look, locations/props, visual QA, draft + self-check are all unchanged. One difference:

- **Do NOT register ARK and do NOT fill `ark_asset_id`** for anything (skip Step 2.3's ARK registration entirely). These references are produced **only as source inputs for Phase 05b keyframe generation** — the same role they already play for lipsync segments.
- Step 3 / Do-Not-Proceed ARK validation does not apply; instead assert **no entry carries `ark_asset_id`**.

(`ark_asset_id` is optional in `reference_list.schema.json`, so a keyframe-path `reference_list` is schema-valid with it omitted.)

---

## Phase 05a — Prompts (no `@assetN`, keyframes deferred)

Handle non-lipsync segments much like lipsync segments for reference wiring:

- **model** = `model_primary` (the chosen non-Seedance model), not `dlai2v_pro`.
- **Prompt**: write the shot-by-shot prompt per `prompt_authoring.md` Section 2 (DP shot-by-shot from `segment.description` + brief), **but do NOT write `@assetN` / `@imageN` placeholders**. Identity and scene are carried by the keyframe, so describe character / scene / action in plain words (same reference discipline as lipsync prompts, but keep the normal non-lipsync content: real cuts, `@audio1` only if the model accepts an audio ref — confirm at Phase 06 — visual-style capper ≤ 15 words, `keep mouth closed, performs through action only` when no one is singing).
- **references[]**: attach the character 2-panel sheet + location / prop as **source refs** (`role=character_asset` / `location_asset` / `prop_asset`) — these are inputs for Phase 05b, **not** fed to Phase 06. **Leave keyframes empty**; Phase 05b backfills `role=keyframe` (do not fabricate keyframe URLs).
- **shot_count** = the number of distinct shot compositions in the segment (model-agnostic, same meaning as for lipsync). This becomes the keyframe count Phase 05b generates; cap 4. Phase 06 maps the generated keyframes onto the final model's frame protocol.
- **Routing**: a keyframe-path project **always proceeds to Phase 05b** (even with zero lipsync segments), because non-lipsync segments now also need keyframes. Do **not** finalize `video_prep` in Phase 05a — hand off to Phase 05b to backfill keyframes and finalize.

**05a validation for keyframe-path non-lipsync segments**: prompt has no `@assetN` / `@imageN`; keyframes empty (pending 05b); source refs present (character + location/prop); `shot_count ∈ [1,4]`. The standard rule "live-action character must have `ark_asset_id`, asset-only" does **not** apply on this path.

## Phase 05b — Keyframes (also for non-lipsync)

Phase 05b runs whenever the project has lipsync segments **or** is on the keyframe path. It processes **both** lipsync segments **and** keyframe-path non-lipsync segments with the **same** machinery (one segment-scoped sub-agent → `gpt-image-2` grid → `split_keyframe_grid.py` → upload → `understand_media` → write back `role=keyframe`). `target_keyframe_count = shot_count`; layout/grid/split/upload/write-back/`ref_id` ordering (`keyframe1..N`) and the `shot_count == 1` single-image case are all identical to lipsync.

The **only** difference is framing, selected per segment by `segment_kind`:

- **`lipsync`** (unchanged): lipsync-safe framing — face clearly visible and recognizable, mouth visible; keep the existing prompt rules. `understand_media` checks include face clearly visible + mouth visible.
- **`non_lipsync_keyframe`**: compose each keyframe as the shot's **opening composition** per the Phase 05a shot design + `segment.description` — correct framing / angle / subject / action-state. The character **need not face camera** and the **mouth need not be visible** (this is an image-to-video seed frame, not a lipsync frame). Lock identity (face / outfit) to the character source ref. **Do NOT inject any lip-sync language** ("sings/speaks with perfect lip synchronization"). `understand_media` checks: identity matches the source ref, the scene / subject / composition match the shot design, and no residual large black border / split-screen remnant / collage text / watermark / distortion — **drop the mouth-visible check**.

Inject `visual_config.visual_style.prompt_modifier` and the helper's `panel_layout_description` for both kinds. Preserve the segment's source refs on write-back exactly as lipsync does.

## Phase 06 — Request (model i2v contract) + path guard + late model change

- **Read the model's image-to-video contract at runtime**: `dl generate-video model <model_primary>` — how many input frames it takes, and which fields (`image_url` single-frame / `keyframes` list / `last_frame_url`), and whether it accepts an audio reference. Do not hardcode; the CLI help is the source of truth.
- **Feed the segment's `role=keyframe` references** (ordered `keyframe1..N`) via that model's i2v fields. **Map the generated keyframe count onto the model's frame protocol**: single-frame model → `keyframe1`; first+last model → `keyframe1` (first) + `keyframeN` (last); multi-keyframe model → all. If the model accepts fewer frames than were generated, keep the first and last (the most load-bearing).
- **Do NOT pass `ark_asset_ids` / `@assetN`**, and **do NOT pass the character / location / prop source refs** — they are baked into the keyframes (same discipline as lipsync). Batch `params` field names use underscores (see `cli_translation.md` Section 3).

### Path guard (defense-in-depth)

Before submitting, assert every non-lipsync job's model and mechanism agree:

- a **non-Seedance** model job must carry **no** `ark_asset_ids` and **no** `@assetN` (it feeds keyframes);
- a **Seedance** model job must use the asset-reference path (standard).

If a job's model and mechanism disagree → **STOP, do not submit**; resolve via "late model change" below. This catches a missed upstream fork (or a model swap) instead of silently shipping a broken request.

### Late model change / model confirmation

The specific non-Seedance model + its request method can be (re-)confirmed here at request time, because the keyframes are model-agnostic seeds:

- **Same path** (non-Seedance → another non-Seedance): cheap, no re-prep. Re-read `dl generate-video model <new>`, re-map the keyframes to its frame protocol, and record the actual model in `video_segments` (`model_used`). The agent decides the switch itself and records it (refund of the failed attempt + new pricing) per `cli_translation.md`; no human approval is required.
- **Path flip** (non-Seedance ↔ Seedance): this changes the mechanism, so it is **not** a same-request swap. Going **to** Seedance needs ARK-registered refs (Phase 04) and may need cross-scene re-segmentation (Phase 02); going **from** Seedance to non-Seedance needs keyframes the project may not have yet. **STOP and route back**: reuse the existing Phase 04 character / location / prop references (they are path-agnostic — no re-generation) to run Phase 05b and produce keyframes; return to Phase 02 only if Seedance cross-scene segments must be re-cut per scene. Never silently emit a request whose mechanism does not match the model.
