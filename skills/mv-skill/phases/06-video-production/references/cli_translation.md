How each segment's `references[]` maps to each model's CLI parameters (which role maps to which flag, placeholder syntax, frame protocol, which fields each model requires) -- **all determined by the current documentation in `video-generation/SKILL.md` + `lipsync/SKILL.md`** -- this file **does not hardcode or restate** those details. This file only covers production discipline specific to music videos that is not in SKILL.md: **failure fallback, precise trim, and batch field name footgun**.

> Lipsync uses `dl lipsync` (LTX 2 series). Single-frame uses `image_url`, multi-frame uses `keyframes` (mutually exclusive). **Which service to use, frame count limits (min/max), each frame's fields (frame_position / frame_ratio / weight), dimension constraints -- always consult `dl lipsync -h` + `lipsync/SKILL.md` directly; this file does not hardcode or restate them.**

## Section 1: Failure Fallback Decision Tree

`failure_policy.ladder`: `retry -> alternate_model -> degrade -> mark_failed`. Each segment is evaluated independently; failures do not affect other segments.

```
A. CLI error / non-2xx -> retry once (exponential backoff 30s)

A'. Lipsync special case (dlai2v_pro): null output / mouth not moving / frozen throughout
    -> most likely keyframe framing is substandard (not MCU+ / full profile / back of head / mouth occluded) or a prompting issue
    -> **do not blindly retry**; if framing is the problem, go back to Phase 05b to regenerate that segment's keyframes; if framing is fine, try switching between single-frame and multi-frame (still dlai2v_pro; fields / commands per `dl lipsync -h`)
    -> status=failed

B. Still fails -> fallback to a model one tier down in the same family (fallback target selected from
   same-family models in video-generation SKILL.md; lipsync fallback: switch between single/multi-frame, or go back to Phase 05b to fix keyframes)
   -> After downgrade, reorganize references per the new model's requirements in SKILL.md
   -> status=degraded + model_used=actual model used
Important: when switching models, the agent decides the switch itself and records it (model_used + the fact that the failed attempt was refunded + the new model's pricing) in `video_segments` for traceability; no human approval is required.

C. Fallback also fails -> retry fallback once
D. Still fails -> status=failed + error description
E. Raw video obtained but video stream duration < segment.duration -> status=failed (cannot be salvaged)
F. Raw video passes -> write `raw_video_url`, and generate `assembly_video_url` (section 2) -> status=generated
```

**Fallback references reorganization**: unsupported roles are removed directly. **A Seedance (asset_reference) segment must not silently downgrade to a non-Seedance model by feeding character `url`s as plain images** — moving the asset_reference path to a non-Seedance model is a **path switch** (the non-Seedance model needs keyframes generated by Phase 05b, not plain character refs), so STOP and surface it (FINALIZE SELF-CHECK / back to Phase 02 or 05b) per `docs/non_seedance_path.md` (Phase 06, late model change); do not fabricate a plain-image request from ARK refs. Same-path fallback (e.g. `seedance-2-0` → `seedance-2-0-fast`) keeps the asset-reference single-path rule: live-action / IP character refs with `ark_asset_id` must be asset-only (`ark_asset_ids` + prompt `@assetN`); do not simultaneously put that ref's `url` into `image_urls` + `@imageN`; location / prop go into `image_urls`. **Keyframe-path request assembly** (non-Seedance non-lipsync) is in `docs/non_seedance_path.md` (Phase 06): feed `role=keyframe` via the model's i2v fields, no ARK.

## Section 2: Raw + Assembly Clip (preventing cumulative drift -- critical)

Every successful segment must retain two URLs:

- `raw_video_url`: model's raw output, for user preview / rollback.
- `assembly_video_url`: precisely trimmed to `segment.duration`, audio stripped, uniform specs, for Phase 07 direct concat.

Generating the assembly clip:

```bash
ffmpeg -i raw.mp4 -t <segment.duration, 3 decimal places> \
  -map 0:v:0 \
  -vf "scale=<target_w>:<target_h>,setsar=1,fps=<target_fps>,format=yuv420p" \
  -c:v libx264 -preset fast -crf 18 \
  -an \
  -avoid_negative_ts make_zero \
  assembly.mp4
```

- No: **`-c copy` is prohibited** -- it snaps at keyframes, causing 0.5-2s drift per segment, **this is the primary cause of cumulative drift** (lip sync goes out of alignment when the full video is concatenated).
- Yes: must re-encode with `-c:v libx264`; output error <= 0.02s.
- Yes: `-t` passes `segment.duration` with 3 decimal places; do not round to whole seconds.
- Yes: must use `-an`; Phase 07 only accepts audio-free assembly clips.
- Yes: target_w / target_h come from `visual_config.resolution`; target_fps uses the most common fps in this batch; default 30.

After assembly, **must verify with ffprobe** (do not trust `-t` -- certain codecs / keyframe densities can make the output 0.1-0.5s longer than `-t`):

```bash
actual_video=$(ffprobe -v error -select_streams v:0 -show_entries stream=duration -of csv=p=0 assembly.mp4)
```

- `|actual_video - segment.duration| <= 0.05s` -> status=generated
- `> 0.05s` -> re-trim once; still fails -> status=failed, report to main agent
- Assembly clip must have no audio stream; raw video's container / audio duration is only used for diagnostics, not for Phase 07 drift assessment.

## Section 3: Batch Field Name Footgun

`dl generate-video` / `dl lipsync --jobs-file=` `params` field names **must always use underscores** -- CLI flags use hyphens (`--image-url`), but batch JSON `params` must use underscores (`image_url`). The CLI uses zod `safeParse` to validate each job: **hyphens / misspelled fields are treated as unknown fields and stripped -> refs not passed through -> model hallucinates faces / null output; missing required fields -> E_SCHEMA error.** This is the most common cause of batch-wide failures.

**Which `params` fields each model accepts, which are required, placeholders (`@image1` / `@asset1` / `@audio1` etc.), single vs multi-frame service -> always consult `dl <verb> -h` / `dl <verb> <service> -h` + `video-generation/SKILL.md` / `lipsync/SKILL.md` directly; this file does not provide a field table.**

Before submitting jobs-file grouped by service, you must write a jobs manifest: `job_key -> segment_id -> service -> params -> source refs`. Lightweight preflight before submission: placeholder numbering does not exceed bounds; the same source ref does not appear in both `ark_asset_ids` and `image_urls`; the same URL / asset is not duplicated; lipsync jobs do not contain both `audio_url` and `duration`; params field names use underscores. After async callback returns, match `job_key` to segment index and write the raw output as `raw_video_url`.

## Section 4: Role -> Who Receives It (MV-specific mapping; field names per section 3, consult CLI directly)

Submit jobs-file grouped by service (`dl lipsync --jobs-file=` / `dl generate-video --jobs-file=`); each entry is `{ "job_key": "seg_NN", ...params }`, params field names use underscores. **Specific field names, single / multi-frame commands, placeholders (`@image1` / `@asset1` / `@audio1`) -- all per section 3, consult CLI / SKILL.md directly. This section only specifies which ref role feeds which segment:**

- **Lipsync segments**: only feed `role=keyframe` (1-4 images, ordered by ref_id `keyframe1..N`; single / multi-frame fields and frame protocol per `dl lipsync -h` / lipsync SKILL.md) + `role=audio_slice` (driving audio). Do not pass `duration`; `audio_url` determines the request duration; `segment.duration` is only used for generating the assembly clip. The `character_asset` (2-panel character reference sheet) / `location_asset` in video_prep for this segment are **source refs used by Phase 05a/05b to generate keyframes; Phase 06 does not pass them to dlai2v_pro** (characters / scenes are already baked into the keyframes).
- **Non-lipsync segments — asset_reference path (Seedance 2.0)**: placeholders use independent per-channel numbering: `@imageN = image_urls[N-1]`, `@assetN = ark_asset_ids[N-1]`, `@audio1 = reference_audio_url`. Registered live-action characters must be asset-only (`ark_asset_ids` + prompt `@assetN`); location / prop go through the plain image channel (`image_urls` + `@imageN`); **the same source ref can only appear in one channel** -- do not also put a live-action character's `url` into `image_urls`.
- **Non-lipsync segments — keyframe path (any other model)**: feed only `role=keyframe` (1-N, ordered `keyframe1..N`, mapped onto the model's i2v frame protocol per `dl generate-video model <model>`) + `role=audio_slice` only if the model accepts an audio ref. **Do not pass `ark_asset_ids`/`@assetN`, do not pass the character/location/prop source refs** (baked into the keyframes — same discipline as lipsync). See `docs/non_seedance_path.md` (Phase 06).

After async callback returns, match `job_key` to segment index, write the raw output as `raw_video_url`, then section 2 produces the `assembly_video_url`.
